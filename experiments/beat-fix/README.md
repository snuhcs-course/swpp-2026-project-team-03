# 건반 파트 박자 보정 실험 (beat-fix)

`ml/beat_align/align.py` 위에 얹어서, 건반(piano + other) 파트의 박·마디선·음 시작/끝을 다듬는 실험 코드입니다. 아직 파이프라인에는 들어가 있지 않습니다.

## 실행

```bash
python experiments/beat-fix/beat_fix.py \
  --keys gated.mid --drums drums_gated.mid --beats beats.json \
  --out-dir out --name "Beautiful Things"
```

- `--keys`: 정렬 전 건반 MIDI (MuScriptor piano+other 7라벨, 무음 게이트 후 `gated.mid`)
- `--drums`: 정렬 전 드럼 MIDI (`drums_gated.mid`). 주면 drum sync가 켜집니다 (파이프라인과 같음).
- `--beats`: Beat This! JSON (`{"beats": [...], "downbeats": [...]}`)
- `--align-dir`: 기본값은 이 저장소의 `ml/beat_align`
- 필요한 패키지: `pretty_midi`, `mido`, `numpy`

출력 (`--out-dir`):

| 파일 | 내용 |
|---|---|
| `<name> - 1_current.mid` | 지금 파이프라인과 같은 `align.py` 결과 (drum sync 켬) |
| `<name> - 6_beats+runs+ends+chords.mid` | 아래 A, B, 1, 2, 3을 모두 적용한 결과 |
| `<name> - report.json` | 채운 박 수, 마디 위상 판단 근거, 옮긴 화음 수 등 |
| `_tmp/` | 중간 파일 |

`--all-variants`를 주면 1·2·3을 하나씩 적용한 버전(A, B 없이)도 함께 씁니다.

## 하는 일

### 박·마디 (정렬 전)

**A. 절반 속도 구간 채우기 (`fill_half_tempo`)**
Beat This!가 한동안 2분음표마다 박을 찍으면(박 간격이 곡 중앙값의 약 2배인 구간이 4개 이상 연속), 그 간격마다 가운데에 박을 하나씩 넣습니다. 그 구간이 2배 빠르게 적히고, 구간 경계에서 마디선이 한 박씩 밀리는 문제를 막습니다. 2배 간격이 하나만 있는 경우는 채우지 않습니다. 시험해 보니 맞을 때만큼 틀릴 때도 많았습니다 (P03은 박 하나를 채우면 다운비트 일치율이 58% → 3%로 떨어짐).

**B. 조건부 마디 위상 (`choose_bar_phase`)**
기본은 `align.py`의 마디 위상(첫 다운비트 + 드럼 백비트 규칙)입니다. "Beat This! 다운비트가 가장 많이 마디 첫 박에 오는 위상"이 이와 다를 때만, 그 위상의 1박에서 건반 화음이 바뀌는 정도가 1.5배 이상일 때 바꿉니다. Beat This!는 곡 전체에서 다운비트를 반 마디 늦게 찍기도 하고, 킥 1·3박 / 스네어 2·4박 곡에서는 드럼으로 반 마디 차이를 구분할 수 없어서, 다운비트 다수결만으로는 바꾸지 않습니다.

### 음 (건반만)

**1. 등간격 화음 묶음 (`fix_runs`, 정렬 전)**
간격이 거의 일정한(±20%) 화음 3개 이상을 묶어서 한꺼번에 격자에 놓습니다 (k번째 화음 = 시작 + k × 간격). 하나씩 반올림하면 조금씩 늦어지는 화음이 중간부터 16분음표 한 칸씩 밀리는데, 이를 막습니다.
- 곡의 화음이 8분음표 자리에 80% 이상 있으면, 8분음표 묶음의 시작을 8분음표 자리에 맞춥니다.
- 시작이 두 자리의 정확히 중간이면, 다른 묶음들이 가장 많이 쓰는 마디 안 위치를 따릅니다.
- 두 묶음이 공유하는 경계 화음은 한 번만 옮깁니다.

**2. 음 끝 붙이기 (`fix_ends`, 정렬 후)**
음 끝이 다음 화음 시작과 16분음표 한 칸 차이면 다음 화음 시작에 맞춥니다 (불필요한 16분 쉼표·겹침 제거).

**3. 화음 끝 맞추기 (`fix_chord_ends`, 정렬 후)**
한 트랙에서 같이 시작한 음들은 같이 끝나게 합니다 (가장 흔한 끝, 트랙의 다음 시작을 넘지 않음). 같은 트랙·같은 시각·같은 음 중복은 하나로 합쳐집니다.

## 결과

데이터: 팀 개발용 24곡의 정렬 전 건반·드럼 MIDI와 Beat This! JSON.

**다운비트 일치율** (Beat This! 다운비트 중 악보 마디 첫 박에 오는 비율, 24곡 평균): 79% → 83%, 나빠진 곡 없음.

| 곡 | 채운 박 | 일치율 |
|---|---|---|
| Warriors | 90 | 23% → 71% |
| Welcome to the Black Parade | 94 | 22% → 68% |
| P07 | 7 | 98% → 99% |
| 그대에게 | 36 | 9% → 10% (마디 위상은 기존 유지, 아래 참고) |

이 지표는 Beat This! 다운비트를 정답으로 삼기 때문에, 다운비트 자체가 틀린 곡에서는 맞지 않습니다. 음 리듬이 맞는지는 반영하지 않습니다.

**MIDI로 확인한 것**
- Beautiful Things 51–60마디: 같은 리듬이 반복되는 구간에서 16분음표 한 칸씩 밀리던 화음(예: 57마디 0, 1, 2.5, 3.5 → 0, 1, 2, 3, 8분음표 단위)이 8분음표 자리로 정리됨. 61–62마디는 등간격 묶음이 아니라 그대로.

**MuseScore로 보고 들어서 확인한 것**
- Big Void: 도입부 개선.
- Warriors: 33마디 이후 마디선이 한 박 밀려 온음표가 "4분음표 + 붙임줄 + 점2분음표"로 쪼개지던 문제 해결.
- 그대에게: B를 조건 없이 적용하면 밴드가 들어오는 음이 마디 3번째 박으로 밀림 → 조건부로 바꿔 기존 위상 유지.

## 남은 문제

- **템포가 바뀌는 곡**: `align.py`는 곡 전체에 템포 하나를 씁니다. Welcome to the Black Parade(판매 악보상 150 → 192)는 A를 적용해도 템포 변화를 담지 못합니다.
- **반 마디 다운비트 오류**: 그대에게처럼 Beat This!가 밴드 구간 다운비트를 반 마디 늦게 찍은 경우, 지금은 "바꾸지 않음"으로만 피합니다. Heroine도 같은 경우일 수 있어 확인이 필요합니다.
- **불규칙한 건반 타이밍**: 등간격 묶음이 아닌 화음(40 ms 넘게 벗어난 화음 중 평균 37%)은 1번 규칙이 다루지 않습니다. Warriors 20–22마디 등.
- **병합 피아노 악보의 성부·쉼표**: 실험5처럼 하나의 피아노 파트로 합치면, 3번을 트랙별로 적용해도 병합 후 같은 보표 안에서 음 끝이 다시 달라져 MuseScore가 성부를 나누고 쉼표를 채웁니다. 병합 후 손별·보표별로 맞추는 것도 시험했지만 해결되지 않았고, 길게 끄는 음(패드, 베이스)이 잘리는 부작용이 있었습니다. 보표를 직접 정하는 MusicXML 출력 쪽에서 다룰 문제로 넘깁니다.

## 시험했지만 넣지 않은 것

| 방법 | 넣지 않은 이유 |
|---|---|
| 오디오(piano+other stem) onset에 음 시작 맞추기 | 6곡 중 5곡에서 격자 오차가 오히려 커짐. 음높이별 onset으로 찾아도 변화 없음 |
| 악기 라벨별 지연 보정 | 라벨별 중앙값이 0–10 ms로 일정한 지연이 없음 |
| 악기 라벨별로 다른 격자 | 라벨 간 차이가 작고(40 ms 초과 16–30%), 병합 후 따로 떨어지는 경우도 0–8% |
| drum sync에서 엇박 드럼 제외 | 최종 위치가 바뀌는 건반 음이 평균 1.3%뿐. 화음마다 다르게 밀리는 오류는 4초 중앙값 구조상 못 고침 |
| 오디오 −20 dB로 음 끝 정하기 | 반복 화음은 오디오와 MuScriptor 모두 다음 타건에서 끝나서 거의 차이 없음 |
| 2배 간격 하나만 있어도 박 채우기 | P03을 망가뜨림 (위 A 참고) |
| B를 조건 없이 적용 | 그대에게처럼 Beat This! 다운비트가 반 마디 틀린 곡을 망가뜨림 |
