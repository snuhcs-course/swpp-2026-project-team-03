# guitar_tab — skyline 리드/리듬 분리 + TAB (비교 기준선)

MuScriptor는 기타 두 대를 한 파트로 합쳐 채보하는 경우가 많아서, 그대로 TAB으로 바꾸면 손이 닿지 않는 운지가 나옵니다.
이 스크립트는 기타 파트가 두 대인지 판단해서, 두 대면 리드와 리듬으로 나누고 한 대면 그대로 두고, 각 파트를 칠 수 있는 TAB으로 만듭니다.

**비교 기준선(baseline)입니다.** 팀의 guitar-guitar 분리 모듈을 대신하지 않고, 그 결과를 같은 지표로 비교하기 위한 출발점입니다.

```
beat_align 출력 MIDI ─▶ 조율 결정 ─▶ 두 대인가? ─┬─ 예 ─▶ skyline 분리 ─▶ 화음 줄이기 ─▶ tuttut 운지 ─▶ .gp5 / .txt / .mid
                                               └─ 아니오 ──────────────▶ 화음 줄이기 ─▶ tuttut 운지 ─▶ .gp5 / .txt / .mid
```

## 동작

1. **조율:** 기타 음의 99% 이상이 들어가는 조율을 표준 → 반음 내림 → Drop D 순서로 고릅니다. 그래도 음역 밖인 음은 옥타브를 옮깁니다.
2. **두 대인지 판단 (자동 모드, 기본):** 아래 "두 대로 나눌지 정하는 규칙"을 보세요 (`decide_split`). `--split always`면 항상 나누고, `--split never`면 나누지 않습니다.
3. **skyline 분리 (두 대일 때):** 같은 시각에 시작하는 음 중 가장 높은 음을 리드로, 나머지를 리듬으로 보냅니다. 리드는 단선율로 만듭니다(다음 리드 음에서 끊음).
4. **화음 줄이기 (기본):** 리듬 파트, 합쳐진 상태 파트, 한 대 파트의 화음은 최대 6음, 개방현을 뺀 운지가 4프렛 안에 들어가야 합니다. 안 되면 가장 낮은 음과 가장 높은 음은 남기고 가운데 음부터 뺍니다. 같은 시각에 같은 음이 겹치면 하나로 합칩니다. `--no-chord-reduction`을 주면 화음을 줄이지 않습니다.
5. **운지:** [tuttut](https://github.com/natecdr/tuttut)(HMM + Viterbi)로 줄·프렛을 고릅니다. 손 이동 벌점 `b=0.1` (기본값 1보다 이동을 강하게 막음).
6. **출력:** MIDI, 텍스트 TAB, Guitar Pro 파일(.gp5). .gp5에는 tuttut가 고른 줄·프렛이 그대로 들어가고, 박자표는 입력 MIDI를 따릅니다(4/4, 12/8 등).

### 두 대로 나눌지 정하는 규칙

MuScriptor는 원곡의 기타 두 대를 한 트랙으로 합쳐 채보하기도 하고, 반대로 한 대가 친 화음에 음을 더 붙이기도 합니다. 그래서 기타 트랙 수만 보고는 두 대인지 알 수 없고, 채보된 음을 직접 봐야 합니다.

먼저 같은 순간에 시작하는 음들을 한 묶음으로 보고, 이 묶음을 기타 한 대로 잡을 수 있는지 확인합니다. 한 줄에 한 음씩, 개방현을 뺀 손가락 위치가 4프렛 안에 들어가야 잡을 수 있다고 봅니다. 이 검사는 화음을 줄이기 전에 합니다. 화음을 줄이고 나면 모든 묶음이 잡을 수 있게 바뀌기 때문입니다.

잡을 수 없는 묶음이 많다고 해서 곧바로 두 대라고 볼 수는 없습니다. 한 대가 친 화음에 음이 몇 개 더 붙어도 잡을 수 없게 되기 때문입니다. 그래서 묶음의 가장 낮은 음과 가장 높은 음이 2옥타브 넘게 벌어져 있는지도 봅니다. 기타 한 대로 한꺼번에 잡는 화음은 보통 6번 줄 개방현(E2)에서 1번 줄 개방현(E4)까지, 즉 2옥타브 안에 들어갑니다. 그보다 넓은 묶음이 자주 나오면 낮은 음역의 리듬 기타와 높은 음역의 리드 기타가 동시에 치고 있다는 뜻입니다.

두 조건을 모두 만족할 때만 두 대로 나눕니다. 잡을 수 없는 묶음이 2% 이상이고 2옥타브 넘게 벌어진 묶음이 3% 이상이면, skyline으로 리드와 리듬을 나눈 뒤 각각 tuttut로 운지를 정합니다. 그렇지 않으면 한 대로 보고, 화음 줄이기(최대 6음, 4프렛 안)만 한 뒤 바로 tuttut로 운지를 정합니다.

파이프라인(`ml/pipeline/unified.py`)은 원곡 라인업이 '모르겠어요'일 때 이 규칙보다 먼저 기타 stem의 스테레오를 봅니다. 왼쪽과 오른쪽이 거의 다른 소리이고(1초 구간 좌우 상관 중앙값 0.2 미만) 좌우가 고르게 나뉘어 있으면(쏠림 중앙값 0.17 미만) 두 대로 보고 `--split always`를 넘깁니다. 두 기타가 같은 음역에서 비슷한 코드를 치는 곡(21 Guns)은 아래 화음 규칙으로는 잡히지 않기 때문입니다.

skyline 규칙은 멜로디 추출 연구의 기준선에서 가져왔습니다. 조율 결정, 화음 줄이기(4프렛), 건너뜀 지표(5프렛)는 이번에 정한 규칙이라 문헌 근거가 없습니다.

## 설치

```bash
cd guitar_tab
pip install -r requirements.txt
```

tuttut는 0.0.7(2026-11-04 배포)을 씁니다. 0.0.6은 옛 numpy·networkx·matplotlib 버전에 묶여 있어 `--no-deps`로만 설치됐고, 운지 계산도 0.0.7에서 새로 짜였습니다.
11/9 테스트 3곡(한페, Sweet Child O' Mine, 우연을 믿어요)의 기타 1·2와 베이스 9개 파트로 두 버전을 비교했습니다(운지 보정 적용 후).

| | 0.0.6 | 0.0.7 |
|---|---|---|
| 처리 시간 (9개 파트) | 68초 | 11.5초 |
| 5프렛 넘는 손 이동 | 38번 | 33번 |
| 개방현 비율 | 12.2% | 12.3% |
| 4프렛 안에 못 잡는 화음 | 0 | 0 |

가장 큰 차이는 한페 기타 1입니다(132마디 중 42마디가 다름). 0.0.6은 7~9마디를 A·D·6번 줄 15~20프렛에 두었고,
0.0.7은 같은 음을 B·1번·D 줄 4~6프렛에 둡니다. 이 파트에서 12프렛 이상인 음은 40%에서 14%로 줄었습니다.
개방현을 고르는 경향은 두 버전이 비슷해서 `refine_positions`는 그대로 필요합니다.

## 사용법

```bash
python skyline_tab.py "song_aligned.mid" out/song/              # 자동 모드: 두 대면 리드·리듬 + 합쳐진 상태 TAB, 한 대면 기타 TAB 하나
python skyline_tab.py "song_aligned.mid" out/song/ --no-merged   # 두 대일 때 합쳐진 상태 TAB은 건너뜀
python skyline_tab.py "song_aligned.mid" out/song/ --split always  # 항상 리드·리듬으로 나눔 (이전 동작)
python skyline_tab.py "song_aligned.mid" out/song/ --split never   # 항상 한 대로
python skyline_tab.py "song_aligned.mid" out/song/ --no-chord-reduction  # 화음을 줄이지 않음 (큰 곡은 1시간 이상)
python verify_gp5.py "out/song/song - skyline lead+rhythm.gp5" out/song/skyline_lead_rhythm.mid
```

출력 (`out/song/`):

| 파일 | 내용 |
|---|---|
| `곡명 - skyline lead+rhythm.gp5` | (두 대) 리드·리듬 두 트랙 TAB. MuseScore, TuxGuitar, Guitar Pro로 열기 |
| `곡명 - guitar.gp5`, `guitar.mid`, `tab_guitar.txt` | (한 대) 기타 한 트랙 TAB, 화음을 줄인 MIDI, 텍스트 TAB |
| `곡명 - merged.gp5` | 나누기 전 합쳐진 상태의 TAB (`--no-merged`면 없음) |
| `skyline_lead_rhythm.mid` | 리드·리듬 두 트랙 MIDI |
| `tab_lead.txt`, `tab_rhythm.txt`, `tab_merged.txt` | 텍스트 TAB |

MIDI에는 줄·프렛 정보가 없어서, MuseScore에서 MIDI를 TAB 보표로 바꾸면 MuseScore가 운지를 새로 정합니다. 이 스크립트의 운지를 보려면 `.gp5`를 여세요.

## 조율 정보 (`tuning.json`)

`skyline_tab.py`와 `bass_tab.py`는 출력 폴더에 TAB이 쓰는 조율을 `tuning.json`으로 남깁니다. 전체 악보 PDF의 조율 안내 문구나 앱 표시에 씁니다.

```json
{"tuning": "half_step_down", "standard": false, "strings": ["D#2", "G#2", "C#3", "F#3", "A#3", "D#4"], "midi": [39, 44, 49, 54, 58, 63]}
```

`strings`·`midi`는 낮은 줄 → 높은 줄 순서입니다. `tuning`: 기타 `standard` / `half_step_down` / `drop_d`, 베이스 `bass_standard` / `bass_half_step_down` / `bass_drop_d` / `bass5_standard`.

## 베이스 TAB (`bass_tab.py`)

베이스는 나누지 않고 tuttut만 씁니다. 정렬된 MIDI의 베이스 트랙(MIDI 프로그램 32~39)을 모아서

1. 같은 시각에 시작하는 음 중 **가장 낮은 음만** 남깁니다 (베이스 라인으로 보고 화음은 뺌).
2. 조율 음역 밖의 음은 옥타브를 옮깁니다.
3. tuttut로 줄·프렛을 고릅니다 (기타와 같은 가중치, `b=0.1`).

**조율 (자동, 기본):** 밴드는 보통 기타와 베이스를 같이 조율하므로, 같은 MIDI의 기타 조율을 따라갑니다. 기타 조율은 위 "동작" 1번 규칙(`choose_tuning`)으로 고르고, 베이스는 그 4현 버전을 씁니다 (표준 → E1 A1 D2 G2, 반음 내림 → D#1 G#1 C#2 F#2, Drop D → D1 A1 D2 G2). 기타 음이 없으면 4현 표준입니다. 기타는 표준인데 베이스만 낮게 조율한 곡은 잡지 못하고, 그런 낮은 음은 옥타브를 올립니다.

```bash
python bass_tab.py "song_aligned.mid" out/song_bass/                                # 자동 (기타 조율 따라감)
python bass_tab.py "song_aligned.mid" out/song_bass/ --tuning bass5_standard        # 조율 직접 지정
```

`--tuning`: `auto`(기본), `bass_standard`, `bass_half_step_down`, `bass_drop_d`, `bass5_standard`(5현, 낮은 B0 추가).

14곡(10곡 테스트셋 + 사용자 평가 3곡, 2곡 겹침) 중 Sweet Child O' Mine만 기타가 반음 내림이라 베이스도 반음 내림이 되고, 나머지는 모두 표준입니다.
출력: `bass.mid`, `tab_bass.txt`, `곡명 - bass.gp5`.

## 전체 악보 MIDI (`full_score.py`)

기타·베이스 처리 결과와 나머지 악기를 한 MIDI로 합칩니다. 순서는 기타(리드·리듬 또는 한 대) → 베이스 → 그 밖의 악기(피아노 등) → 드럼입니다.
정렬된 MIDI의 기타·베이스 트랙은 처리된 것으로 바꾸고, 나머지 트랙은 그대로 복사합니다. 템포·박자표·해상도는 정렬된 MIDI를 따릅니다.
기타 음색은 파트(리드·리듬 또는 한 대)마다 다수결로 정합니다. 처리된 각 음이 정렬된 MIDI에서 같은 시각·같은 음이름의 원래 음에 붙어 있던 음색을 세고, 가장 많은 것을 씁니다(동점이면 첫 기타 트랙 음색).
나일론(24)으로 정해지면 스틸 통기타(25)로 바꿉니다. TAB은 20프렛까지 쓰는데 클래식 기타는 보통 19프렛이기 때문입니다.

```bash
python skyline_tab.py "song_aligned.mid" out/song/
python bass_tab.py    "song_aligned.mid" out/song_bass/
python full_score.py  "song_aligned.mid" out/song/ out/song_bass/ out/song_full_score.mid
```

베이스 폴더에 `bass.mid`가 없으면 베이스 없이 합칩니다 (정렬된 MIDI의 원래 베이스도 넣지 않음).
MuseScore로 열면 네 악기를 한 악보로 볼 수 있습니다. 운지는 MIDI에 없으므로 TAB은 각 `.gp5`를 여세요.

## 키보드 연주 가능하게 (`piano_playable.py`)

`full_score.py`는 합치기 전에 키보드 트랙(GM 0-7 피아노류, 16-23 오르간류)을 두 손으로 칠 수 있게 줄입니다 (`--no-keyboard-limit`이면 그대로 복사).
MuScriptor가 길게 누른 화음(신스 패드 등)을 16분음표마다 다시 누르는 화음으로 적거나, 3옥타브에 걸친 9~10음 화음을 내는 경우가 있어서입니다.

1. 다시 누르기 합치기: 한 음이 16분음표마다(중간에 16분 하나까지 빠져도 됨) 6번 이상 이어서 다시 눌리면 하나의 긴 음으로 합칩니다. 8분음표마다 반복하는 것은 그대로 둡니다.
2. 손 제한: 같은 순간에 시작하는 음 중 오른손은 맨 위 음부터 14반음(9도) 아래까지, 왼손은 맨 아래 음부터 14반음 위까지 맡고, 어느 손에도 안 들어가는 음은 뺍니다. 손마다 최대 5음이고, 넘치면 바깥 음(오른손 맨 위, 왼손 맨 아래)은 남기고 옥타브 중복 음부터 뺍니다.

피아노 stem이 피아노/일렉 피아노/오르간 트랙으로 나뉘어 있어도 한 사람이 치는 것으로 보고 함께 제한하며, 같은 순간 두 트랙에 있는 같은 음은 하나만 남깁니다.
같은 순간에 시작하는 음만 봅니다. 앞에서 누른 채 이어지는 음은 세지 않으므로, 길게 누른 화음 위로 빠른 아르페지오가 지나가는 구간(예: Heavy Is the Crown 88~91마디)은 여전히 한 사람이 치기 어려울 수 있습니다.

```bash
python piano_playable.py "song_aligned.mid" out/song_keys.mid
```

## 한계

- 반주만 나오는 구간에서는 반주 화음의 맨 위 음이 리드로 가서, 리드가 반주 윗선을 따라 칩니다.
- 반주가 리프보다 높거나 두 기타가 같은 음역에서 교차하면 거꾸로 나뉩니다.
- 리드가 높은 프렛(17~20)에 놓이는 경우가 있습니다. 손 이동은 적지만 연주자들이 흔히 쓰는 위치와 다를 수 있습니다.
- 건너뜀 비율은 텍스트 TAB에서 잰 간이 지표라 실제 연주 난이도를 다 반영하지 않습니다.
- tuttut 계산은 동시음이 많을수록 급격히 느려집니다. 화음을 줄이면 곡당 몇 분 안이고, `--no-chord-reduction`이면 합쳐진 상태가 곡에 따라 1시간 이상 걸립니다.
- 화음 줄이기는 음을 뺍니다. 합쳐진 상태 TAB은 MIDI의 모든 음을 담지 않습니다.
- .gp5의 곡 제목은 cp1252만 저장되므로 한글 제목은 로마자로 씁니다(파일 이름은 한글 그대로).
