# PR #15·#17·#18 적용 버전과 배포 버전 비교 (2026-11-09 KST)

사용자 평가 인터뷰 3곡을 같은 라인업으로 두 번 돌려, 배포 전인 세 PR을 합친 버전과
지금 앱이 쓰는 배포 버전의 결과를 비교한 기록이다. 세 PR은 볼륨에 배포하지 않았다.

## 0. 결론

- 원곡 구성 판단이 바뀐 곡은 **한 페이지가 될 수 있게** 하나다. 배포 버전은 기타 1대로 보고
  둘째 기타를 MIDI-GPT로 생성했고, PR 적용 버전은 스테레오 판정으로 기타 2대를 찾아 둘 다
  원곡에서 채보했다. 원곡은 기타 2대다.
- Sweet Child O' Mine과 우연을 믿어요(적재)는 두 버전의 판단이 같다.
- Sweet Child의 AI 피아노는 한 칸(16분음표)에 동시에 시작하는 음이 최대 12개에서 5개로 줄었다
  (생성 키보드에 `piano_playable` 적용).
- TAB 운지, GP5 박 단위 표기, drum sync 가드의 효과는 이 비교에서 수치로 확인하지 않았다(3절).

## 3. 확인하지 않은 것

- TAB 운지(`refine_positions`)와 GP5 박 단위 표기(`beat_pieces`): 앱이 받는 결과에 GP5가 없어
  PDF를 눈으로 비교해야 한다. 인터뷰 지적 위치: Sweet Child 기타 110·111·136마디,
  Sweet Child 베이스 13·17~18·52마디, 적재 베이스.
- drum sync 가드(`grid_guard`): 한페 베이스 1:23~1:33을 두 버전 MP3로 들어 봐야 한다.
- 청취 평가와 구매 악보 비교.

## 4. 진행 중 생긴 문제

- **볼륨 용량:** 테스트 출력의 분리 음원(곡당 490~730 MB)이 쌓여 `/data`가 20 GB 중 97%가
  찼고, 그 상태에서 앱 경로로 올린 3곡이 모두 BS-RoFormer 단계에서 실패했다
  (`soundfile.LibsndfileError: System error`). 테스트 폴더의 `stems`, 입력 WAV,
  `node_modules`를 지워 여유 공간 2.7 GB로 되돌린 뒤 다시 돌렸다. 볼륨이 빠듯하므로 테스트
  출력은 바로 정리하고, PVC 증설이나 오래된 결과 정리가 필요하다.
- **원곡 구성 직접 지정:** 원곡 구성을 '키보드 없음'으로 지정해 한페를 돌리면 키보드 stem을
  채보하지 않고 MIDI-GPT가 키보드를 새로 만든다. 사용자가 없다고 했지만 실제로 크게 들리는
  악기를 알려 주는 장치는 아직 없다 (`faint_parts`는 반대 방향만 다룬다).
